# 온케어 · 병원 IT 지원센터 화면 시연

`병원_하드웨어_장애지원_요구사항.md`를 바탕으로 만든 동작형 프런트엔드입니다. 외부 폰트·CDN·서비스에 접속하지 않습니다.

## 실행

간단히 `index.html`을 Edge 또는 Chrome으로 열어 사용할 수 있습니다. 브라우저에서 로컬 파일 저장을 제한하는 경우 Node.js가 설치된 PC에서 이 폴더의 `server.cjs`를 실행하세요.

```powershell
node server.cjs
```

브라우저에서 `http://127.0.0.1:4173`에 접속합니다. 서버는 해당 PC에서만 접근할 수 있도록 설정되어 있습니다. 종료는 실행 터미널에서 Ctrl+C를 누릅니다.

## 시연 방법

1. 직원 모드에서 장비 또는 자주 찾는 가이드를 선택합니다.
2. 단계별로 미해결을 선택하면 마지막 단계에서 접수로 연결됩니다. 해결을 선택하면 자가 해결 세션으로 기록됩니다.
3. 안전상 조치가 불가능하면 수행 불가를 선택하고 사유를 적어 접수할 수 있습니다.
4. 진료 중단 등은 긴급 접수 버튼을 사용합니다.
5. 접수 시 연락처·위치를 입력합니다. 장비 식별정보와 사진은 선택입니다.
6. 오른쪽 위 역할 선택에서 ‘전산 · 김전산’ 또는 ‘전산 · 이전산’으로 전환합니다.
7. 신청 상세에서 담당자를 지정하고, 지정된 담당자 모드에서 처리 시작 후 조치 내용을 입력해 완료합니다.
8. 통계 분석에서 기간·장비·증상·부서·담당자·상태·긴급 여부로 필터링하고 XLSX 파일을 내려받습니다.
9. 가이드 관리에서 증상 및 조치 단계를 추가·수정하고 미리보기를 확인합니다.

## 구현 범위

- 대시보드, 4종 장비·9개 초기 가이드, 단계별 조치
- 일반·긴급 접수 및 사진 첨부
- 본인·같은 부서 목록과 전산 전체 목록의 화면 구분
- 검색·필터, 상세 및 조치 이력, 담당 지정과 3단계 상태
- 사이트 내 알림과 읽음 처리
- 집계 카드, 장비별·부서별 현황, 7일 추이, 증상 순위, 담당자별 완료 현황
- 필터를 적용한 집계 요약 및 접수 목록의 실제 XLSX 다운로드
- 순차형 가이드 추가·수정·미리보기, 수정 전 접수 이력 보존
- 좁은 창과 모바일 너비에 맞춘 레이아웃

## 실제 운영과의 차이

이 결과물은 화면과 업무 흐름 확인용입니다. 우측 역할 선택은 시연 기능이며 실제 인증·접근 제어 기능이 아닙니다. 병원 계정 연동, 서버 권한 검사, 공용 DB, 파일 서버, 감사 로그 및 백업은 연결되지 않았습니다. 실제 환자정보나 운영 접수를 입력하지 마세요.

데이터는 현재 브라우저의 `localStorage`에만 저장됩니다. 다른 PC와 공유되지 않습니다. 사진도 같은 저장소를 사용하므로 브라우저 저장 한도에 영향을 받습니다. 사진은 JPG·PNG·WebP 최대 3장, 장당 2MB로 제한합니다. 시연 상태는 새로고침 후에도 유지되며 브라우저 사이트 데이터 삭제 시 초기화됩니다.

같은 브라우저의 다른 탭에서 변경하면 최신 상태를 읽고 상세창을 닫아 다시 확인하도록 안내합니다. 서버 기반 동시 수정 제어를 대체하지는 않습니다.

가이드 편집은 순차형 조치에 한정하며 저장 즉시 적용합니다. 요구사항의 임의 질문 분기, 초안·게시 분리 및 순환 경로 검증은 실제 구축 단계의 확장 대상입니다. 안내 문구는 사용 전 전산 담당자의 장비별 검토가 필요합니다.

알림은 시연 역할 그룹 단위로 표시하며 모두 읽음을 지원합니다. 실제 사용자별 수신, 담당자 개인별 알림 및 상세 링크 연결은 서버 연동 단계에서 구현합니다.

## 확인한 내용

- JavaScript 문법 검사
- 브라우저에서 자가 조치 2단계 → 미해결 종료 → 접수 → 이력 자동 전달
- 접수 저장 → 김전산 지정 → 처리 중 → 조치 입력 후 완료
- 새로고침 후 접수 및 완료 이력 유지
- 직원 모드에 타 부서 신청과 통계 메뉴가 표시되지 않는지 확인
- 통계 화면의 필터 및 집계 내용 표시
- XLSX ZIP 구조·CRC 및 XML 파싱 검사

병원 계정 연동 및 실제 보안 권한 검증, 다중 사용자 동시 처리와 임상 환경 시험은 수행되지 않았습니다.

## 제조사·모델 선택 추가

- PC: 삼성·HP / 일반 프린터: 삼성
- 장비 선택 후 제조사·모델을 선택하고 증상 안내로 이동합니다. 자주 찾는 가이드에서도 동일하게 선택합니다.
- 삼성 PC 기본 모델은 타워형 DB400TFA·DB400TEA·DB400T9B와 슬림형 DB400S6B·DB400S9B입니다. 다른 모델은 등록하거나 모델 직접 입력·모델 모름을 사용할 수 있습니다.
- 전산 담당자 모드 → 가이드 관리 → 장비 모델 관리에서 실제 모델명을 등록하면 해당 제조사의 모델 목록에 표시됩니다.
- 모니터·바코드/라벨 프린터의 제조사는 직접 입력하거나 모름을 선택합니다.
- 긴급 접수에서도 장비에 맞는 제조사·모델을 선택할 수 있습니다. 장비·제조사 변경 시 이전 모델을 초기화합니다.
- 제조사·모델이 접수 목록·상세 및 엑셀 접수 목록에 저장됩니다. 목록 검색으로 제조사와 모델명을 검색할 수 있습니다.
- 모델별 전용 조치 내용은 아직 없으며 현재는 기존 장비 공통 안내를 제공합니다.
- 추가 확인: 브라우저에서 HP 선택 → 조치 안내 → 일반 접수 → 목록·상세에 HP 및 모델 모름 저장, 긴급 접수에서 삼성 프린터로 장비 변경 및 모델 직접 입력 표시를 확인했습니다.

## 모델별 제품 이미지

- 삼성 PC에서 DB400TFA·DB400TEA·DB400T9B·DB400S6B·DB400S9B를 선택하면 해당 모델의 대표 이미지가 즉시 표시됩니다.
- 제조사를 변경하면 모델과 이전 이미지를 초기화합니다. 이미지가 없는 모델은 미등록 안내를 표시합니다.
- 기존 브라우저 저장 데이터를 보존하면서 기본 모델 목록을 합쳐 표시합니다.
- 이미지 원본은 assets 폴더에, 이미지별 출처는 assets/sources.json에 보관합니다. DB400TFA·DB400TEA는 신성씨앤에스 제품 페이지, DB400T9B는 삼성전자 지원 페이지의 이미지를 사용했습니다.
- model-images.js 및 단일 HTML에는 이미지가 내장되어 있어 외부 인터넷 접속 없이 표시됩니다. 출처 링크는 사용자가 선택할 때만 외부 사이트를 엽니다.
- 이미지는 제품군 대표 이미지입니다. 세부 모델·출고 구성에 따라 실제 장비 외관이 다를 수 있으므로 장비 라벨을 함께 확인합니다.
- 브라우저에서 세 모델의 이미지 로딩 및 모델 변경 시 교체, HP로 변경 시 이미지 초기화를 확인했습니다.

### 슬림형 모델 추가

- 모델 선택 목록을 타워형(DB400T)·슬림형(DB400S)으로 나누어 표시합니다.
- DB400S6B·DB400S9B를 선택하면 슬림형 배지와 공간 활용에 대한 설명을 제공합니다.
- DB400S6B 이미지는 다나와의 DB400S6B-BIZ1 자료, DB400S9B 이미지는 삼성전자 2020년 7월 카탈로그의 PDF 8쪽에 있는 원본 내장 이미지를 사용합니다. DB400S9B 사진의 모니터와 주변기기는 대표 구성 예시입니다.
- 두 슬림형 모델 모두 브라우저에서 선택·이미지 로딩·상호 교체를 확인했습니다. 이미지 파일은 단일 HTML에도 포함됩니다.

## 조치 단계별 이미지 등록

1. 오른쪽 위 시연 역할을 전산 담당자로 전환합니다.
2. 가이드 관리에서 원하는 증상의 **조치 단계 관리**를 선택합니다.
3. 각 단계에 조치 설명을 작성하고 **참고 이미지 등록**에서 파일을 선택합니다.
4. 이미지 설명을 선택적으로 입력합니다. 기존 이미지는 같은 입력란에서 교체하거나 이미지 삭제 버튼으로 제거합니다.
5. **직원 화면 미리보기**로 설명·이미지와 단계 연결을 확인합니다.
6. **저장 및 적용**을 누르면 새로 시작하는 직원 안내에 반영됩니다.

- 이미지는 단계당 1장, JPG·PNG·WebP, 장당 최대 2MB입니다. 선택 후 이미지가 정상 디코딩되는지도 검사합니다.
- 조치 단계 추가·삭제·위/아래 이동을 지원합니다. 단계 이동 시 설명과 이미지가 함께 이동합니다. 단계 수는 1~20개입니다.
- 이미지는 선택 항목이며 기존 텍스트 가이드는 수정 없이 동작합니다.
- 입력 내용과 이미지는 저장 및 적용 전에는 반영되지 않습니다. 저장 공간이 부족하면 기존 저장 내용을 유지하고 현재 편집 내용으로 재시도할 수 있게 안내합니다.
- 이미지가 포함된 조치를 진행한 후 접수하면, 그때의 이미지와 설명을 접수 이력에 보존합니다. 이후 가이드 이미지가 삭제·변경되어도 기존 신청 이력은 바뀌지 않습니다.
- 이미지는 현재 브라우저에 저장됩니다. 다른 직원 PC와 공유하려면 실제 구축 단계에서 DB 및 파일 서버를 연결해야 합니다.
- 확인한 항목: 실제 JPG 등록, 이미지 설명 입력, 단계 이동 시 이미지 동반 이동, 미리보기, 저장 후 직원 안내 표시, 접수 이력 저장, 가이드 이미지 삭제 후 기존 접수 이미지 보존.
- 화면 캡처의 본체 이미지는 기능 검증용 예시이며 실제 조치 사진으로 등록한 기본 콘텐츠가 아닙니다.

## 조치 참고 이미지 기본 등록

- 기존 9개 장애 가이드의 18개 조치에 맞춘 SVG 안내 그림을 기본으로 제공합니다. 전원·프로그램·USB·모니터·프린터·라벨 점검을 단계별로 구분한 설명용 도식입니다.
- 이미지를 생성하는 코드는 default-step-images.js에 있으며, 생성된 원본 18개와 단계별 연결 목록은 assets/guide-steps/ 폴더에 있습니다.
- 웹에서 가져온 사진이나 AI가 생성한 사진이 아니라 코드로 그린 안내 도식입니다. 실제 장비의 버튼·포트 위치는 다를 수 있음을 그림 안에 표시합니다.
- 새 데이터 및 기존 브라우저 데이터에 모두 적용합니다. 처음 업데이트를 열 때 이미지가 없는 현재 단계에 자동 등록하고 기존 사용자 이미지는 보존합니다.
- 한 번 적용한 이후 관리자가 이미지를 삭제하면 새로고침해도 다시 채우지 않습니다. 기존 접수의 이미지·버전은 변경하지 않습니다.
- 관리자의 이미지 등록 기능은 계속 JPG·PNG·WebP만 허용합니다. SVG는 앱에서 생성하는 기본 도식에 한해 이미지 표시 기능에서 지원합니다.
- 모든 이미지는 HTML 안의 데이터로 표시되어 인터넷에 접속하지 않습니다.
- 검증: 18개 SVG XML 검사, 안내 내용별 연결 검사, 일회성 데이터 반영·기존 이미지 보존·기존 접수 보존·이후 삭제 유지 검사, 실제 브라우저에서 18개 이미지 정상 로딩과 직원 안내 표시를 확인했습니다.

## 샘플 신청 160건 추가

PC 100건, 일반 프린터 30건, 모니터 20건, 바코드·라벨 프린터 10건을 기존 데이터에 한 번만 추가합니다. 추가분은 완료 96건, 처리 중 32건, 접수 32건이며, 부서 6곳과 담당자 2명에 분산됩니다. 완료 건에는 실제 경과시간과 조치 내용을 가진 가상 이력을 제공합니다. 제조사·모델과 장비 식별정보도 포함됩니다. 기존 접수·가이드·사용자 등록 이미지는 유지하며 새로고침 시 중복 생성하지 않습니다. 직원 모드는 같은 부서와 본인 신청만 표시하므로 전체 샘플은 전산 담당자 모드에서 확인합니다.


## 토너 신청·재고
부서는 프린터 모델·토너 품번·수량으로 신청합니다. 신청 시 재고를 예약하고 전산 담당자의 접수 후 실물 수령 완료 시에만 출고합니다. 취소 시 예약을 해제합니다. 전산 담당자는 품목 등록, 입고 수량 저장, 입출고 이력 조회를 할 수 있습니다. 대시보드는 수령 완료일 기준 월간 사용 수량과 최근 6개월 사용량을 표시합니다. 품목별 실재고/예약/신청 가능 수량, 부족 기준을 제공합니다.

초기 토너 3개 품목과 신청 5건은 명시적인 시연 데이터이며 실제 삼성 모델·토너 호환 정보가 아닙니다. 실제 프린터 모델과 토너 품번은 전산 담당자가 등록해야 합니다. 데이터는 기존 oncare-v1 브라우저 저장소에 유지됩니다. 실제 병원에서 공동 재고로 운영하려면 병원 인증, 서버 데이터베이스, 권한 검증과 서버 원자적 재고 차감이 필요합니다. 현재 역할 선택기는 시연용입니다.


## 일산차병원 브랜딩
왼쪽 메뉴에 일산차병원 공식 홈페이지 로고를 원래 비율과 색상으로 표시하고, 브라우저 제목·상단 경로·하단에 병원 명칭을 표시합니다. 출처: https://ilsan.chamc.co.kr/ (로고: https://ilsan.chamc.co.kr/asset/img/ilsan_CI.svg). 로고 원본은 assets/ilsan-cha-logo.svg에 보관하며 시연 HTML에는 내장하여 외부 접속 없이 표시합니다.


## 장비 제조사·모델 관리
전산 담당자 전용 메뉴에서 PC·모니터·일반 프린터·바코드/라벨 프린터별로 제조사를 등록하고 제조사별 모델번호를 추가합니다. 새 제조사는 모델 없이 등록할 수 있으며 직원의 선택 목록에 즉시 표시됩니다. 기존 기본 모델과 이전 catalog 데이터를 유지합니다. 동일 장비 내 제조사명 및 동일 제조사의 모델명은 공백·대소문자·전각 문자를 정규화해 중복을 방지합니다. 시연 데이터는 기존 브라우저 저장소에 보관됩니다.


## 대시보드 증감률·추이
대시보드 4개 집계 카드는 기존 누적 건수를 유지하고 최근 7일과 이전 7일의 신규 신청 건수를 비교합니다. 한국시간 오늘 00:00부터 역산한 달력일 기준으로 오늘 포함 7일과 이전 7일을 집계합니다. 상태별 카드는 현재 상태로 분류한 신청 코호트이며 과거 시점의 대기·처리 잔량이 아닙니다. 이전 기간 0건/현재 양수는 신규 발생, 양쪽 0건은 변동 없음으로 표시합니다. 7일 그래프와 실제 기간별 수량을 함께 표시합니다. 직원은 같은 부서 조회 범위, 전산은 전체 범위를 적용합니다. 통계 화면의 기존 기간 집계는 유지됩니다.


## 대시보드 헤더 배경
인사말 영역에 연한 하늘색 그라데이션, 병원 건물 벡터 일러스트와 심전도 포인트를 추가했습니다. 건물은 디자인용 일반 일러스트이며 실제 일산차병원 사진이 아닙니다. 배경 SVG는 로컬 내장되어 내부망·단일 HTML에서도 표시됩니다. 긴급 장애 접수 버튼과 역할별 사용자 인사말을 유지합니다.


## 6개월 가상 토너 이력
최초 반영 시점을 기준으로 이번 달 포함 최근 6개월에 180건의 완료 신청을 생성합니다. 월별 추가 건수는 22·28·24·34·32·40건이며 6개 부서와 3개 시연 토너 품목에 분산합니다. 각 월의 출고와 동일 수량의 가상 입고를 생성하여 기존 실재고·예약·신청 가능 수량을 보존합니다. 기존 신청과 사용자 품목을 유지하며 batch 표식으로 새로고침 중복 생성을 방지합니다. 가상 신청은 TN-SIM6 번호 및 메모로 식별합니다. 대시보드에 월별 사용 수량과 신청 건수를 함께 표시합니다.


## 토너 월별 세로 막대그래프
토너 사용량을 최근 6개월의 세로 막대로 나란히 표시합니다. 공통 Y축은 0부터 시작하고 같은 눈금과 비율로 높이를 계산합니다. 막대 위 사용 수량과 아래 월·신청 건수, 이번 달 표시를 유지합니다. 기존 집계와 가상 데이터는 변경하지 않습니다.


## 첫 진입 인트로 홈페이지
사이트 실행·새로고침 시 홈페이지형 인트로를 표시합니다. 로고·상단 메뉴, 병원 이미지 배너, 실제 가이드 검색, 서비스 바로가기 4개, 지원센터 안내와 소개를 제공합니다. 로그인 버튼은 병원 인증 미연동을 알리고 기존 시연 역할로 대시보드를 여는 선택창입니다. 실제 전화번호·운영시간이 제공되지 않아 확인 안내로 표시하며 예시 번호를 사실로 등록하지 않습니다. 업무 화면의 홈페이지 메뉴로 다시 돌아올 수 있습니다.
배경 출처: https://ilsan.chamc.co.kr/asset/img/og_image.jpg (일산차병원 공식 홈페이지 공개 이미지). 배경을 HTML에 내장해 외부 접속 없이 표시합니다.

인트로 병원 배경을 사용자 제공 사진 282103_1.jpg로 교체했습니다. 원본 비율은 유지하고 가로 배너에 맞춰 CSS 배경 위치를 조정하며, 왼쪽 안내 문구의 그라데이션을 유지합니다.


## 스마트 병원 배경·반투명 패널·로그인 카드
사용자 첨부 로그인 디자인의 병원·네트워크 배경을 기반으로 고정 문구와 폼을 정리한 배경 이미지를 생성했습니다. 전체 홈페이지 배경으로 표시하고 헤더·서비스·센터 패널에 반투명 배경과 블러를 적용합니다. 로그인은 동일 배경 위 흰색 카드와 파란 버튼 디자인을 적용합니다. 실제 병원 인증과 SSO는 아직 미연동이므로 아이디·비밀번호 입력과 아이디 저장은 비활성화하고 시연 역할 로그인만 동작합니다. SSO·비밀번호 찾기·원격지원 버튼은 연결 준비 안내를 표시하며 사용자 가이드는 기존 가이드로 연결됩니다. 원본 자산은 assets/intro-smart-hospital.png이며 HTML에도 내장합니다.


## 업무 화면 배경 통일
인트로와 동일한 스마트 병원 배경을 업무 페이지에도 재사용합니다. 고정 배경 레이어에 블러·낮은 불투명도를 적용하고 대시보드 카드·조회 패널·필터·표·접수 모달에 반투명 표면을 제공합니다. 글자 전체에 opacity를 적용하지 않고 표·입력·상태 표시의 대비를 유지합니다. 인트로·스마트 로그인 스타일은 독립적으로 유지하며 데이터·권한·집계·접수 흐름은 변경하지 않습니다. 좁은 화면과 투명도 감소 설정에서는 패널을 더 불투명하게 표시합니다.
